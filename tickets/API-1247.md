# API-1247: Add `POST /v1/refunds`

**Type**: Story
**Reporter**: product@payments.example
**Assignee**: backend-team
**Priority**: P1
**Sprint**: 2026-S22
**Status**: Ready for dev

## Context

The Payments API creates payments today (`POST /v1/payments`) but offers no way
to refund them. Product needs a dedicated refunds endpoint to separate the audit
and accounting reconciliation flows.

## Request

Add a **`POST /v1/refunds`** operation that creates a full or partial refund of
an existing payment.

### Expected input

- `paymentId` (uuid, required): source payment.
- `amount` (integer, minor units, optional): when absent, full refund.
- `reason` (string, optional, max 280 characters): free-text reason.

### Expected output

A `Refund` object:

- `id` (uuid)
- `paymentId` (uuid)
- `amount` (integer)
- `currency` (string, inherited from the source payment)
- `status` (enum: `PENDING`, `SUCCEEDED`, `FAILED`)
- `createdAt` (date-time)

### Business rules

- A payment can be refunded only when its status is `CAPTURED`.
- The sum of refunds must not exceed the payment amount.
- `amount` must be > 0 when provided.

### Expected errors

- `404` when `paymentId` is unknown.
- `409` when the payment is not `CAPTURED` or when the sum exceeds the amount.
- `422` when `amount ≤ 0`.

## Non-functional

- Must be audited (JWT, observability, RFC 7807).
- The endpoint must appear in `/actuator/prometheus` (standard HTTP metrics).
