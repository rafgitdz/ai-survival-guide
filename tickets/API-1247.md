## Contexte

Aujourd'hui l'API Payments crée des paiements (`POST /v1/payments`) mais ne
permet pas de les rembourser. Le produit a besoin d'un endpoint dédié aux
remboursements pour distinguer les flux d'audit et de réconciliation comptable.

## Demande

Ajouter une opération **`POST /v1/refunds`** qui crée un remboursement total
ou partiel d'un paiement existant.

### Entrée attendue

- `paymentId` (uuid, requis) — paiement source.
- `amount` (integer, minor units, optionnel) — si absent, remboursement total.
- `reason` (string, optionnel, max 280 caractères) — motif libre.

### Sortie attendue

Un objet `Refund` :

- `id` (uuid)
- `paymentId` (uuid)
- `amount` (integer)
- `currency` (string, hérité du paiement source)
- `status` (enum : `PENDING`, `SUCCEEDED`, `FAILED`)
- `createdAt` (date-time)

### Règles métier

- Un paiement ne peut être remboursé que s'il est en statut `CAPTURED`.
- La somme des remboursements ≤ montant du paiement.
- L'`amount` doit être > 0 si fourni.

### Erreurs à prévoir

- `404` si `paymentId` inconnu.
- `409` si le paiement n'est pas `CAPTURED` ou si la somme dépasse le montant.
- `422` si `amount ≤ 0`.

## Non-fonctionnel

- Doit être audité (JWT, observabilité, RFC 7807).
- L'endpoint doit apparaître dans `/actuator/prometheus` (métriques HTTP standard).
