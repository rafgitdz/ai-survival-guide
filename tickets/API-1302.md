# API-1302: Publish the Payments API v2

**Type**: Story
**Reporter**: product@payments.example
**Assignee**: backend-team
**Priority**: P1
**Sprint**: 2026-S24
**Status**: Ready for dev

---

## Context

The payments squad has prepared the next version of the Payments API in
`openapi/payments-v2.yaml`. The version currently in production is described in
`openapi/payments-v1.yaml`. Two partner integrations consume the production
contract, and the Semver rule of `AGENTS.md §3` applies: no breaking change
ships without a major bump and a `CHANGELOG.md` entry.

Product wants to ship the candidate in the next release train. Before that,
the backend team must know exactly what changes for consumers and how to roll
it out without breaking them.

## Objective

Decide, with evidence, how `payments-v2.yaml` can be published: as a drop-in
update of the current API, or as a new major version living alongside it.

## Tasks

1. Compare `openapi/payments-v1.yaml` (before) and `openapi/payments-v2.yaml`
   (after). List **every** change with its severity (`MAJOR`, `MINOR`, `PATCH`)
   per the repository Semver rule. The list must be exhaustive, not a summary.
2. Give the overall Semver verdict for the candidate.
3. Check that the candidate's `info.version` and base path are consistent with
   that verdict. Report any mismatch.
4. Based on the report, propose an evolution plan covering:
   - the version bump,
   - the path strategy (`/v1`, `/v2`, both),
   - the deprecation of the current version (RFC 8594 `Deprecation` / `Sunset`
     headers, timeline, consumer communication),
   - the `CHANGELOG.md` entry.
5. **Stop at the plan.** Do not modify any file before the plan is approved.
   Scope of this ticket: the OpenAPI specs, `CHANGELOG.md` and an ADR. Java
   code, build and tests are handled by a follow-up ticket.
6. At the end, list the skills you used and what each one contributed.

## Definition of Done

- [ ] Exhaustive change list with per-change severity.
- [ ] Overall Semver verdict.
- [ ] Evolution plan presented and approved by the backend team.
- [ ] No file modified before approval.
